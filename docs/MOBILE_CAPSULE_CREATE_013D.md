# Mobile capsule creation — Prompt #013D

The protected `create-capsule` route is reachable from the list and creates a text-only self-capsule through the existing `createCapsule` service. It uses labeled React Native text inputs for a local `YYYY-MM-DD` date and 24-hour `HH:MM` time. These native-compatible controls work with the existing Expo Go setup and add no dependency, though they are manual entry fields rather than a calendar or clock picker. Check punctuation entry, accessibility and keyboard behavior on Android devices.

Validation rejects blank text, NUL, more than 2,000 Unicode code points, invalid local dates and times, and times outside the client clock's future/90-day window. The backend remains authoritative. Local time resolution checks the runtime's selected instant against the requested components and searches adjacent instants within 26 hours for another matching local minute. It rejects nonexistent and ambiguous local minutes, including half-hour DST folds. It converts a valid instant to UTC ISO 8601. Confirmation displays title, local date/time, timezone and UTC offset, with the server-time warning. The instant and timezone are rechecked on submit; a change requires another review. This relies on the device's timezone database and JavaScript local-time behavior, which must be validated on target Android devices, including unusual timezone changes.

The submission controller prevents concurrent taps and never retries automatically. Missing/invalid session and 401/403, or 422 validation errors, allow a safe correction or retry. Network/timeout, 503 and other failures where a commit cannot be ruled out lock further submission and direct the user to refresh the list. A successful response clears message state and replaces the route with a fresh capsule list. Abort and disposal suppress stale completion on unmount or session change. Form content stays in memory and is not put into navigation parameters or logs; the message input disables autocomplete and autocorrect. Operating-system keyboards may have their own privacy behavior. A session refresh may remount the form and discard an unfinished draft.

Mocked Node tests cover validation, Unicode lengths, ISO generation, DST gap and folds, duplicate submission, uncertain outcomes, abort and stale completion, success navigation and clearing, and submitted-content routing. The existing list tests cover a fresh list's initial fetch. From `apps/mobile`, `npm run typecheck` passed, `npm run lint` passed after fixing an initial JSX lint error, and `npm test` passed 17 tests. No live API or Supabase requests were made. Node mocks do not prove Expo Router native navigation, actual refresh on Android, input behavior or session lifecycle; those require device testing. No backend, migration or dependency changes were made.
