# Mobile API foundation — Prompt #013B

`apps/mobile/lib/api.ts` exposes `authenticatedRequest` for GET and POST with optional JSON, explicit expected statuses and a response parser. It obtains the Supabase session, checks the expected user and expiry, attaches the bearer token, rejects redirects, and provides a 10-second default deadline and caller cancellation. The deadline includes session retrieval. `getAuthenticatedUser` remains compatible with Home. Errors contain a safe category and, for unexpected HTTP statuses, a numeric status; response content and credentials are never logged or included. No POST is retried. Parsers receive `undefined` for 204/205 and malformed JSON fails closed.

`apps/mobile/lib/capsules.ts` exports request/response types plus `createCapsule`, `listCapsules`, `revealCapsule` and `cancelCapsule`. It sends only the three create fields, checks pagination bounds, validates and encodes capsule UUIDs, checks exact response fields and verifies returned reveal/cancellation IDs. List metadata excludes bodies; reveal text is returned only to its caller and is not cached or persisted. Client validation does not replace server validation or the server time gate.

The tests use Node's built-in test runner with the already-installed TypeScript compiler to transpile the real modules in memory. Supabase and fetch are mocked; no new dependency or live service is used. Run from `apps/mobile`: `npm test`. Coverage includes Home authentication compatibility, headers, changed/expired sessions, response status and shape failures, 401/403/404/422/503, network, timeout, abort, no POST retry, pagination, list privacy, reveal and cancellation.

Verification from `apps/mobile`: `npm run typecheck` passed; `npm run lint` passed after correcting a test-only ESLint global declaration; `npm test` passed 8 tests. From the repository root, `git diff --check` passed with LF-to-CRLF warnings; it excludes untracked files. The backend suite was not rerun because no backend code changed. No server or Supabase was contacted.

Callers must abort requests on unmount or account change and discard stale results, clear revealed content from UI state, and provide user-facing errors. The expected-user check occurs at session retrieval; it does not monitor subsequent account changes. Creation has no idempotency key: after a timeout or connection failure its outcome can be uncertain, so do not automatically repeat it. HTTP status 404 does not identify why a capsule is unavailable. Android runtime, real networking and live authentication are not verified by the mocked Node tests. Next: implement the read-only list screen in a separately scoped task.
