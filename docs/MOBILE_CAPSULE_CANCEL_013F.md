# Mobile capsule cancellation — Prompt #013F

The protected detail screen offers a visually distinct Cancel capsule action. It opens a confirmation explaining permanence, reveal denial and server-controlled eligibility; no cancellation request is made until Confirm cancellation is pressed. The existing `cancelCapsule` service sends the request and validates its response. The controller prevents concurrent or duplicate submissions and never automatically retries. Device time and list status do not decide eligibility.

On a validated success the controller immediately clears revealed text and metadata, enters a cancelled state with no reveal/cancel actions, and the screen replaces the detail route with a fresh capsule list. Missing sessions and 401/403 show a safe session message; a 404 shows generic unavailability. Network errors, timeout, 503, explicit request cancellation and malformed or unexpected responses can occur after a commit, so they clear detail data, block further actions and direct the user to refresh the list before trying again. No response body, token, header or private text is logged or persisted.

The existing focus/session/route lifecycle disposes the controller, aborts outstanding requests, clears memory state and discards late responses. The on-screen back action is disabled during cancellation. A hardware back action, logout or process interruption can still leave the outcome unknown after dispatch; abort does not undo a server commit. Refresh the list before a later attempt. This slice does not coordinate future invitation or notification cancellation.
